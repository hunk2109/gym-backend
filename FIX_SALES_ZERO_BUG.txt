🔧 BUG FIX: VENTAS MUESTRAN 0 EN PANTALLA

═══════════════════════════════════════════════════════════════════

PROBLEMA REAL:

Las ventas NO se cargaban porque el endpoint estaba en el orden INCORRECTO
en el controlador de backend.

En NestJS, el orden de los decoradores @Get() IMPORTA MUCHO.

Problema de Routing:
  ├─ Endpoint genérico: @Get(':id')
  ├─ Endpoint específico: @Get('date-range/:startDate/:endDate')
  
Si el específico está DESPUÉS del genérico:
  └─ /sales/date-range/2025-12-02.../2025-12-03... 
     ↓
     Se interpreta como: /sales/{id} 
     donde id = "date-range"
     ↓
     ❌ No encuentra el ID y retorna error 404

═══════════════════════════════════════════════════════════════════

LA SOLUCIÓN:

Mover el endpoint de date-range ANTES del :id en SalesController

ARCHIVO: gym-backend/src/modules/sales/sales.controller.ts

ANTES (orden incorrecto):
  └─ GET daily-revenue
  └─ GET :id          ← Genérico atrap todos después
  └─ POST
  └─ PUT :id
  └─ DELETE :id
  └─ GET date-range   ← ❌ Nunca se alcanza!

DESPUÉS (orden correcto):
  └─ GET statistics
  └─ GET member/:memberId
  └─ GET top-products
  └─ GET daily-revenue
  └─ GET date-range/:startDate/:endDate  ← ✓ Específico ANTES
  └─ GET :id                              ← Genérico DESPUÉS
  └─ POST
  └─ PUT :id
  └─ DELETE :id

═══════════════════════════════════════════════════════════════════

POR QUÉ SUCEDÍA:

1. Flutter llama: GET /api/sales/date-range/2025-12-02.../2025-12-03...

2. NestJS router interpreta:
   "¿Es /sales/:id?"
   "Sí, :id = date-range"
   
3. Busca una venta con ID "date-range"
   
4. No la encuentra
   
5. Retorna 404 → SalesService retorna [] (lista vacía)
   
6. UI muestra "No hay ventas" ❌

═══════════════════════════════════════════════════════════════════

CAMBIO REALIZADO:

Movimiento de 5 métodos en el controlador:

1. Daily-revenue (después de top-products)
2. Date-range (ANTES de :id) ← CRÍTICO
3. :id (después de date-range)

LECCIÓN: ORDEN DE RUTAS EN NESTJS

En NestJS, el orden de los decoradores @Get() es CRÍTICO:

✓ CORRECTO:
  @Get('specific-path')   ← Rutas específicas PRIMERO
  @Get('other-specific')
  @Get(':id')             ← Ruta genérica AL FINAL

✗ INCORRECTO:
  @Get(':id')             ← Genérica ATRAPA todo
  @Get('specific-path')   ← Nunca se alcanza
  @Get(':id')

Esto se llama "Route Precedence" - rutas más específicas ANTES que genéricas.
