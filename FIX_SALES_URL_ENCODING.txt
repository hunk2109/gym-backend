🔧 BUG FIX: VENTAS RETORNA 200 PERO SIN DATOS

═══════════════════════════════════════════════════════════════════

PROBLEMA IDENTIFICADO:

El endpoint devolvía 200 OK pero sin datos.

REQUEST: GET /sales/date-range/2025-12-02T22:43:12.247Z/2025-12-03T22:43:12.247Z
RESPONSE: 200 OK
DATA: []  ❌ (debería devolver 10 ventas)

ROOT CAUSE:

Cuando Flutter llama al endpoint con fechas ISO8601 en el path:
  /sales/date-range/2025-12-02T22:43:12.247Z/2025-12-03T22:43:12.247Z

Dio (cliente HTTP) automáticamente URL-encod ifica la URL:
  /sales/date-range/2025-12-02T22%3A43%3A12.247Z/2025-12-03T22%3A43%3A12.247Z

Pero NestJS NO decodificaba los parámetros del path automáticamente.

Resultado:
  - startDate recibido: "2025-12-02T22%3A43%3A12.247Z"  (ENCODED)
  - startDate esperado: "2025-12-02T22:43:12.247Z"  (DECODED)

Cuando NestJS intentaba parsear "2025-12-02T22%3A43%3A12.247Z" como fecha:
  new Date("2025-12-02T22%3A43%3A12.247Z")
  └─ Retorna: Invalid Date ❌

TypeORM entonces hacía un query con fechas inválidas:
  WHERE createdAt BETWEEN "Invalid Date" AND "Invalid Date"
  └─ Retorna: 0 filas ❌

═══════════════════════════════════════════════════════════════════

LA SOLUCIÓN:

Decodificar los parámetros del path en el controlador usando decodeURIComponent()

ARCHIVO: gym-backend/src/modules/sales/sales.controller.ts

MÉTODO: @Get('date-range/:startDate/:endDate')

ANTES:
```typescript
async getSalesByDateRange(
  @Param('startDate') startDate: string,
  @Param('endDate') endDate: string,
) {
  return this.salesService.getSalesByDateRange(startDate, endDate);
  // startDate = "2025-12-02T22%3A43%3A12.247Z"  ❌ ENCODED
}
```

DESPUÉS:
```typescript
async getSalesByDateRange(
  @Param('startDate') startDate: string,
  @Param('endDate') endDate: string,
) {
  // Decodificar los parámetros de la URL
  const decodedStartDate = decodeURIComponent(startDate);
  const decodedEndDate = decodeURIComponent(endDate);
  
  return this.salesService.getSalesByDateRange(decodedStartDate, decodedEndDate);
  // decodedStartDate = "2025-12-02T22:43:12.247Z"  ✓ DECODED
}
```

   └─ Retorna: 10 filas ✓

7. Controller retorna:
   200 OK
   data: [ { id, totalAmount, ... }, ... ]  ✓

8. Flutter recibe y muestra 10 ventas con total $210.00 ✓

CARACTERES AFECTADOS POR URL-ENCODING:

Los caracteres especiales en ISO8601 que causa problemas:
  `:` → %3A  (separador de hora)
  `T` → No se encod ifica
  `Z` → No se encod ifica
  `.` → No se encod ifica
  `-` → No se encod ifica

Así que en la URL quedaría:
  2025-12-02T22%3A43%3A12.247Z
  ├─ 2025-12-02 ✓ (sin cambios)
  ├─ T22%3A43%3A12 ❌ (: convertidos a %3A)
  └─ .247Z ✓ (sin cambios)

LECCIÓN: URL-ENCODING EN PATHS

Cuando usas parámetros en el path de una URL (no query params):
  ❌ NO haces: GET /api/resource/:param
     donde param = "2025-12-02T22:43:12.247Z"
     
Porque se transforma en: GET /api/resource/2025-12-02T22%3A43%3A12.247Z

✓ MEJOR hacer: GET /api/resource
  con queryParameters: ?startDate=2025-12-02T22:43:12.247Z&endDate=...
  (Dio maneja automáticamente el encoding/decoding)

O SI DEBES USAR PATH PARAMS:
  Decodifica siempre en el backend:
  ```typescript
  @Param('startDate') startDate: string
  const decoded = decodeURIComponent(startDate);
  ```
